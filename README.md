# Telegram PIN Login

Учебное клиент-серверное приложение с входом через одноразовый PIN Telegram. Сервер и клиент оформлены как **два самостоятельных проекта**:

| Проект | Содержимое | Запуск |
| --- | --- | --- |
| [server](server/README.md) | Express API, aiogram-бот, ngrok | `make -C server run` |
| [client](client/README.md) | Flet-приложение с QR и полем PIN | `make -C client run` |

Каждую папку можно скопировать отдельно. Сервер не импортирует клиент и не запускает его. Клиент обращается к API только по HTTP-адресу из своего `.env`. Закрытие Flet не останавливает сервер.

## Окружения и настройки

Всего два Python-окружения:

```text
server/
  .venv/              # Python-зависимости бота и серверного launcher
  .env                # общие настройки API и бота, секреты
  requirements.txt
  api/                # TypeScript/Express, свои npm-зависимости
  bot/
  run.py
  Makefile
  start.bat
client/
  .venv/              # Flet, HTTP-клиент и генерация QR
  .env                # только API_BASE_URL и BOT_USERNAME
  requirements.txt
  app/
  run.py
  Makefile
  start.bat
```

`server/api/node_modules` — зависимости Node.js, а не дополнительное Python-окружение. При переносе на другой компьютер окружения не копируют: их создают заново из requirements.txt. `.env` и локальные зависимости исключены из Git.

## Быстрый запуск на настроенном ноутбуке

Откройте два терминала PowerShell **в корне проекта**, где находятся папки `server` и `client`. Повторно устанавливать зависимости или активировать `.venv` перед каждым запуском не нужно: Makefile использует Python нужного проекта напрямую.

В первом терминале запустите сервер:

```powershell
make -C server run
```

Дождитесь сообщения **«Сервер готов»**. Launcher сам собирает API, запускает ngrok и бота, обновляет адрес туннеля и проверяет webhook Telegram. Оставьте этот терминал открытым.

Во втором терминале запустите клиент:

```powershell
make -C client run
```

Если терминал уже открыт внутри `server` или `client`, используйте просто `make run`.

Для остановки клиента закройте окно Flet. Для остановки сервера нажмите `Ctrl+C` в первом терминале. При следующем запуске запросите новый PIN. Альтернативный запуск — двойной щелчок по `server/start.bat` и затем `client/start.bat`.

### Если команда make не найдена

Проверьте `make --version`. После установки Make закройте старые терминалы и откройте новые; если терминал встроен в VS Code, полностью перезапустите VS Code.

На Windows с установленным winget GNU Make можно установить один раз:

```powershell
winget install --id ezwinports.make --exact --source winget
```

### Проверка входа и доставки сообщения вручную

1. В окне клиента проверьте QR-код и кнопку перехода к боту. Оба должны открывать вашего Telegram-бота.
2. Отправьте боту `/start`. Введите полученный шестизначный PIN в клиенте и нажмите «Войти». Должен появиться ваш профиль Telegram; отсутствие фамилии или аватара допустимо.
3. Отправьте из приложения короткое тестовое сообщение администратору. Проверьте **и подтверждение в приложении, и фактическое получение текста в Telegram администратора**. В сообщении должен быть указан правильный отправитель.
4. Закройте клиент и запустите его снова, оставив сервер работающим. Повторный вход по уже использованному PIN должен отклоняться. Отправьте новый `/start` и войдите по новому коду.
5. Чтобы проверить замену кода, запросите два PIN подряд без входа между запросами: первый должен отклоняться, последний — работать. Каждый код действует не больше 15 минут и подходит только для одного успешного входа.

Это инструкция для ручной проверки с настоящим Telegram. Результаты автоматических тестов не подтверждают получение сообщения в реальном чате. Если отправка не удалась, проверьте `ADMIN_CHAT_ID` в `server/.env`, отправьте боту `/start` из аккаунта администратора и перезапустите сервер после изменения настроек.

## Установка с нуля

Нужны Python 3.12, Node.js 24 LTS и npm; для команд Makefile — GNU Make. На сервере также нужны ngrok, его authtoken и Telegram-бот от [BotFather](https://t.me/BotFather).

Настройте проекты по их отдельным инструкциям:

- [Установка и запуск сервера](server/README.md)
- [Установка и запуск клиента](client/README.md)

Для локальной демонстрации клиент использует `API_BASE_URL=http://127.0.0.1:3000`. Для клиента на другом компьютере потребуется доступный с этого компьютера адрес API и соответствующая сетевая настройка сервера; ngrok в текущем запуске публикует webhook бота, а не API.

## Проверки

Из корня этой рабочей папки:

```powershell
make -C server test
./server/.venv/Scripts/python.exe tests/local_smoke.py
```

Последний файл — проверка **совместной работы двух проектов**, поэтому остаётся в общем каталоге `tests`. Он запускает настоящий локальный HTTP-обмен и подменяет только Telegram; настоящие сообщения не отправляются. Для обычного запуска папка `tests` не нужна ни серверу, ни клиенту.

## API

- `GET /health` — ответ `200 {"status":"ok"}`.
- `POST /internal/pins` — выдача PIN ботом, требует `X-Internal-Key`.
- `POST /auth` — вход по `{"key":"123456"}`, возвращает профиль и accessToken.
- `POST /messages` — отправка текста администратору, требует Bearer accessToken.
- Бот принимает `POST /telegram/webhook` на своём порту и защищённый `POST /internal/messages` от API.

Профили, PIN и сессии хранятся в памяти сервера, без базы данных. Перезапуск API сбрасывает вход. Ответы администратора обратно во Flet не доставляются.
