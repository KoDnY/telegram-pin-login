## Implementation Strategy / координация агентов

- На каждый Tnnn создать нового исполнителя, не назначать тому же агенту следующую задачу.
- Здесь доступны до трёх исполнителей одновременно плюс главный координатор; независимые задачи ставить в очередь.
- Каждый агент читает spec.md, plan.md, свою задачу, релевантный контракт и AGENTS.md.
- Если graphify-out/graph.json существует, перед исследованием кода сначала graphify query. Граф может отставать от документов; актуальные контракты и спецификация приоритетны.
- Разрешённые файлы — перечисленные в задаче; необходимость других изменений согласовать с координатором.
- Отчёт исполнителя: изменённые файлы, результат проверок, ограничения, короткое объяснение для начинающего.
- Координатор сверяет результат с критерием задачи, выполняет интеграционные проверки и только после этого отмечает [x].
- Общий tasks.md меняет только координатор; секреты не включать в промпты и отчёты.
- Блокировка одной задачи не разрешает выполнять зависящие от неё.
- Исправления внутри той же задачи направлять её исполнителю; следующий TaskID получает новый агент.
- Публичные сообщения/настоящая отправка теста администратору выполняются только с явным разрешением пользователя на такую проверку. Тесты по умолчанию используют подмену доставки.
