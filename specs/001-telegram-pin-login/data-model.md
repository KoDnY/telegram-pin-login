# Data model: временные объекты в памяти

Базы данных нет. Все серверные объекты исчезают при перезапуске API.

## UserProfile

- telegramId: положительное безопасное целое JSON.
- firstName: непустая строка.
- lastName, username: строка или null.
- avatar: null либо {mimeType: image/jpeg | image/png, base64: string}, до 1 MB исходных байтов.
Профиль поступает только от доверенного бота. Отсутствие опциональных полей не мешает входу.

## PinRecord

- pin: строка по шаблону ^[0-9]{6}$.
- telegramId: владелец.
- issuedAt, expiresAt: серверное время; expiresAt = issuedAt + 15 минут.
Map pin → запись и обратная Map telegramId → pin.
Состояния: active → consumed / expired / replaced. Терминальные записи удаляются.
Повторный /start удаляет старую запись и выдаёт другой код.
При одновременном auth только один запрос атомарно забирает активную запись.
Периодическая очистка удаляет просроченные записи; проверка срока выполняется также при auth.

## Session

- token: криптографически случайная строка.
- telegramId: владелец.
Создаётся при успешном auth; токен не выводить в лог.
Map token → telegramId. Действует до перезапуска API; клиент не сохраняет на диск.
Профиль хранится в Map telegramId → UserProfile.
Новый PIN не отменяет уже созданные сессии: отменяется только предыдущий PIN.

## AdminMessage (без постоянного хранения)

- text: trim, 1–3000 символов.
- sender: определяется по серверному токену, а не из тела запроса клиента.
- delivery: отправляется по цепочке API → бот → Telegram; результат accepted или ошибка.
Telegram message_id может возвращаться как подтверждение принятия.
История переписки, ответы администратора, очередь и хранение сообщений не входят в объём.
