# Настройка и запуск на Windows

Компоненты реализованы. Локальные проверки описаны в [validation.md](validation.md). Результаты локальной и последующей ручной проверки приведены в validation.md. Для нового запуска настройте собственные значения ниже.
Все команды ниже выполняются в PowerShell из корня проекта.

## Зависимости

Нужны Node.js 24 LTS, Python 3.12 и ngrok. Установка ngrok и учётная запись: https://ngrok.com/docs/getting-started/ .

```powershell
npm.cmd --prefix api ci
py -3.12 -m venv bot/.venv
py -3.12 -m venv client/.venv
./bot/.venv/Scripts/python.exe -m pip install -r bot/requirements.txt
./client/.venv/Scripts/python.exe -m pip install -r client/requirements.txt
```

При повторном запуске с уже установленными зависимостями создавать окружения заново не нужно. Корневое `.venv` для этих команд не используется. Flet установлен с desktop-зависимостями; при первом открытии окна может понадобиться интернет для загрузки нативного runtime.

## Локальные настройки

Копировать примеры только при отсутствии `.env`, чтобы сохранить введённые значения:

```powershell
foreach ($component in 'api', 'bot', 'client') {
    if (-not (Test-Path "$component/.env")) {
        Copy-Item "$component/.env.example" "$component/.env"
    }
}
```

Создай два разных секрета. Команда выводит значение только в твоём локальном терминале; не присылай его в чат:

```powershell
./bot/.venv/Scripts/python.exe -c "import secrets; print(secrets.token_hex(32))"
```

Запусти её дважды: первый результат запиши как `INTERNAL_API_KEY` в **оба** файла `api/.env` и `bot/.env`, второй — как `WEBHOOK_SECRET` только в `bot/.env`. Секреты и `.env` не публикуются.

## Создать Telegram-бота

1. Открой официального https://t.me/BotFather . Отправь `/newbot`.
2. Задай отображаемое имя и уникальный username с окончанием `bot`.
3. Полученный токен вставь локально в `bot/.env`: `BOT_TOKEN=...`. Не отправляй токен в чат и не добавляй в Git.
4. В `client/.env` запиши `BOT_USERNAME=...` без символа `@`.

## Настроить ngrok и запустить компоненты

В локальном терминале выполни команду подключения токена из своего ngrok Dashboard:

```powershell
ngrok config add-authtoken <твой-ngrok-authtoken>
```

Терминал 1 — собрать и запустить API:

```powershell
npm.cmd --prefix api run build
node api/dist/server.js
```

Проверка в другом терминале: `Invoke-RestMethod http://127.0.0.1:3000/health` возвращает `status: ok`. Дополнительный режим разработки — `npm.cmd --prefix api run dev`; для демонстрации выше используется проверенный запуск собранного сервера.

Терминал 2 — туннель:

```powershell
ngrok http 8080
```

Скопируй HTTPS Forwarding-адрес без завершающего `/` в `bot/.env`, поле `PUBLIC_BASE_URL`. Оставь локальные адреса API и бота из примеров.

Терминал 3 — бот:

```powershell
./bot/.venv/Scripts/python.exe -m bot.app.main
```

Бот регистрирует `/telegram/webhook` с отдельным секретом и проверяет регистрацию. Polling не используется. Пока `ADMIN_CHAT_ID` пустой, вход работает, а отправка админу будет отклонена.

## Узнать свой ADMIN_CHAT_ID

1. С собственного аккаунта Telegram открой созданного бота и отправь `/start`.
2. На этом ноутбуке открой http://127.0.0.1:4040 — локальный инспектор ngrok.
3. Найди входящий запрос `POST /telegram/webhook`. В JSON тела возьми числовое `message.chat.id` именно своего личного сообщения.
4. Запиши число в `bot/.env` как `ADMIN_CHAT_ID=...`. Перезапусти бота (Ctrl+C, затем команда запуска). Этот аккаунт будет получать сообщения из приложения.

Инспектор содержит данные сообщений и заголовок секрета webhook; не публикуй его содержимое. Для настройки не нужны сторонние боты определения ID.

Терминал 4 — окно клиента:

```powershell
./client/.venv/Scripts/python.exe -m client.app.main
```

Отправь боту новый `/start`, введи PIN в окне. PIN действует 15 минут, одноразовый; новый `/start` отменяет предыдущий. После входа отправь тестовый текст себе как админу. Ответы администратора в приложение не доставляются.

После смены адреса ngrok обнови `PUBLIC_BASE_URL` и перезапусти бот. Для завершения останови клиент, бот, API и туннель; штатная остановка бота удаляет webhook. После перезапуска API старые PIN и сессии потеряны: получи новый код.

## Проверки без реального Telegram

```powershell
npm.cmd --prefix api run build
npm.cmd --prefix api test
./bot/.venv/Scripts/python.exe -m pytest bot/tests -q
./bot/.venv/Scripts/python.exe tests/local_smoke.py
```

Последняя команда запускает настоящий локальный HTTP-обмен всех компонентов с тестовой Telegram-сессией, без отправки настоящему админу. Она не подтверждает работу ngrok или внешнего Telegram.

## Ручная проверка демонстрации

- `/health` отвечает `ok`.
- `/start` выдаёт PIN, Flet показывает правильный профиль и фото либо заглушки.
- Повторное использование, старый PIN после нового `/start`, истёкший и неизвестный код отклоняются.
- Два пользователя получают свои профили.
- Текст из приложения приходит выбранному админу с подписью отправителя; успех показывается после подтверждения Telegram.
- При ошибке доставки интерфейс сообщает об ошибке; при timeout — о неизвестном результате, без автоматической повторной отправки.
- После перезапуска API старый токен отклоняется, новый вход работает.
